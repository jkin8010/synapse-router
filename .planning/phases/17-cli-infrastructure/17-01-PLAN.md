```typescript
/**
 * Determine whether the current process is running in an interactive terminal.
 * Returns false when stdin/stdout are not TTYs, when running in a known CI
 * environment, or when the user explicitly requests non-interactive mode.
 *
 * Per D-07: checks process.stdin.isTTY && process.stdout.isTTY
 * Per D-08: checks CI, GITHUB_ACTIONS, GITLAB_CI, CODEBUILD_BUILD_ID, JENKINS_URL, TF_BUILD
 * Per D-09: non-TTY auto-degrades (returns false, caller decides behavior)
 * Per D-10: --no-interactive flag in process.argv overrides everything
 */
export function isInteractive(): boolean {
  // --no-interactive flag takes highest priority (per D-10)
  if (process.argv.includes("--no-interactive")) return false;

  // Non-TTY stdin or stdout means non-interactive (per D-07)
  if (!process.stdin.isTTY || !process.stdout.isTTY) return false;

  // Known CI/automation environments — even with pseudo-TTY, not interactive (per D-08)
  const ciEnvs = [
    "CI",
    "GITHUB_ACTIONS",
    "GITLAB_CI",
    "CODEBUILD_BUILD_ID",
    "JENKINS_URL",
    "TF_BUILD",
  ];
  for (const env of ciEnvs) {
    if (process.env[env]) return false;
  }

  return true;
}
```

The function is pure — no side effects, no imports beyond Node.js built-ins. Callers (prompts.ts, command handlers) use the return value to decide whether to prompt or fail/use-defaults.

Do NOT add any default exports — use named exports only matching the project convention.

Create apps/cli/src/utils/prompts.ts. Per D-16, wrap all 5 listed prompt types: select, checkbox, confirm, input, search. Also add promptPassword (needed by Plan 03 for setup.ts API key entry). Per D-17, each wrapper checks isInteractive() before prompting.

Design principles:
1. **Lazy import**: `@inquirer/prompts` is dynamically imported (`await import("@inquirer/prompts")`) so non-interactive CLI runs never load the dependency.
2. **TTY gate**: When `!isInteractive()`, check for `--yes` flag (per D-12) to return defaults, otherwise throw with a clear actionable error listing the needed flags.
3. **Static defaults**: Use static defaults (not `@inquirer/prompts`' built-in defaults) so non-interactive mode returns the same defaults without loading the package.
4. **picocolors**: Not used in prompts.ts directly — prompts handle their own rendering. Available for commands that import it separately.

Implement these six exported functions with the following signatures:

```typescript
import { isInteractive } from "./tty.js";

// --- Internal helpers ---

function hasYesFlag(): boolean {
  return process.argv.includes("--yes");
}

function requireInteractive(reason: string): never {
  throw new Error(
    `Cannot prompt in non-interactive mode: ${reason}. ` +
    `Use --yes to accept defaults or provide values via flags.`
  );
}

// --- Public API ---

export interface SelectOption<T = string> {
  name: string;
  value: T;
  description?: string;
}

// promptSelect: choose one from a list
export async function promptSelect<T = string>(
  message: string,
  choices: SelectOption<T>[],
  opts?: { defaultIndex?: number; pageSize?: number }
): Promise<T>;

// promptCheckbox: multi-select from a list
export async function promptCheckbox<T = string>(
  message: string,
  choices: SelectOption<T>[],
  opts?: { defaults?: T[]; pageSize?: number; required?: boolean }
): Promise<T[]>;

// promptConfirm: yes/no confirmation (returns boolean)
export async function promptConfirm(
  message: string,
  opts?: { defaultVal?: boolean }
): Promise<boolean>;

// promptInput: free-form text input (returns string)
export async function promptInput(
  message: string,
  opts?: { defaultVal?: string; required?: boolean; validate?: (v: string) => true | string }
): Promise<string>;

// promptSearch: type-to-filter selection
export async function promptSearch<T = string>(
  message: string,
  source: (term: string | undefined) => Promise<SelectOption<T>[]>,
  opts?: { pageSize?: number }
): Promise<T>;

// promptPassword: hidden text input (for API keys, passwords)
export async function promptPassword(
  message: string,
  opts?: { validate?: (v: string) => true | string }
): Promise<string>;
```

Each function body follows this pattern:
1. Check `isInteractive()` — if false, check `hasYesFlag()` and return default or throw `requireInteractive()`.
2. If interactive, `const { select/checkbox/confirm/input/search/password } = await import("@inquirer/prompts");`
3. Call the @inquirer/prompts function with the mapped options.
4. Return the result.

For promptPassword specifically: when `!isInteractive()`, always throw — the --yes flag cannot supply a password. The error message should guide users to provide the key via `--api-key` flag or vault.

For promptSelect: the `defaultIndex` option maps to the @inquirer/prompts `default` parameter (which expects the value, not the index). Use `choices[opts.defaultIndex].value` as the default.

For promptCheckbox: `defaults` array maps to `checked: opts?.defaults?.includes(c.value)` on each choice.

For promptSearch: the `source` function receives `term: string | undefined`. When `--yes` is set, call `source(undefined)` and return the first result.

Import isInteractive from "./tty.js" (ESM requires .js extension in TypeScript imports — TypeScript resolves .ts to .js).

All functions are async and return Promise<T>.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry -> apps/cli | @inquirer/prompts and picocolors are downloaded from npm as dependencies |
| process.env -> tty.ts | CI env vars (CI, GITHUB_ACTIONS, etc.) cross the trust boundary from the execution environment |
| process.stdin/stdout -> tty.ts | isTTY property is a Node.js runtime property, not attacker-controlled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Tampering | npm dependency (@inquirer/prompts) | accept | Pinned major version (^8.4); npm registry is the distribution channel; supply chain risk is inherent to npm ecosystem; `pnpm audit` recommended post-install |
| T-17-02 | Spoofing | tty.ts CI env detection | mitigate | CI env vars (GITHUB_ACTIONS) are set by the CI platform, not attacker-controlled; user-controlled env vars (e.g., process.env.CI=true set by a malicious script) could suppress interactive prompts, but this is a non-security UX degradation — the --no-interactive flag provides explicit user opt-in |
| T-17-03 | Information Disclosure | prompts.ts input wrapper | mitigate | promptInput for sensitive values (API keys) does not echo by default since @inquirer/prompts input type only echoes typed characters; for truly hidden input, promptPassword uses OS-level masking; values are returned to caller in memory and not persisted by prompts.ts |
| T-17-04 | Denial of Service | prompts.ts non-TTY path | mitigate | When !isInteractive() and no --yes flag, functions throw immediately with an actionable error message and do not hang waiting for stdin; this prevents CI pipeline hangs (Pitfall 1 from PITFALLS.md) |
</threat_model>

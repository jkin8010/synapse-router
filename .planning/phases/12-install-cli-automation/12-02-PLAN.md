    **Step 2: Create .github/workflows/publish.yml**
    Create file `.github/workflows/publish.yml` with EXACT content (per D-04, RESEARCH.md canonical pattern, PATTERNS.md pattern):

    ```yaml
    name: Publish to npm

    on:
      push:
        tags:
          - 'v*'

    jobs:
      publish:
        runs-on: ubuntu-latest
        permissions:
          contents: write      # Required for GitHub Release creation
          id-token: write      # Required for npm provenance (OIDC token flow)

        steps:
          - uses: actions/checkout@v6

          - uses: actions/setup-node@v4
            with:
              node-version: '22'
              registry-url: 'https://registry.npmjs.org'

          - uses: pnpm/action-setup@v4
            with:
              version: 10

          - name: Install dependencies
            run: pnpm install --frozen-lockfile

          - name: Build all packages
            run: pnpm build

          - name: Run tests
            run: pnpm test

          - name: Derive version from git tag
            id: version
            run: |
              VERSION="${GITHUB_REF_NAME#v}"
              echo "Publishing version: $VERSION"
              echo "version=$VERSION" >> $GITHUB_OUTPUT

          - name: Publish @synapse-router/skill
            run: |
              pnpm --filter @synapse-router/skill exec pnpm version ${{ steps.version.outputs.version }} --no-git-tag-version
              pnpm --filter @synapse-router/skill publish --provenance --access public --no-git-checks
            env:
              NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}

          - name: Publish @synapse-router/install-skill
            run: |
              pnpm --filter @synapse-router/install-skill exec pnpm version ${{ steps.version.outputs.version }} --no-git-tag-version
              pnpm --filter @synapse-router/install-skill publish --provenance --access public --no-git-checks
            env:
              NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}

          - name: Create GitHub Release
            run: |
              gh release create ${{ github.ref_name }} --generate-notes
            env:
              GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    ```

    **Key design decisions (for executor understanding, NOT to be added to the YAML file):**

    1. Trigger `push: tags: v*` — per D-04: tag push only. Tags like `v0.1.0`, `v1.0.0` match the pattern.

    2. `--frozen-lockfile` — ensures reproducible CI builds. Lockfile is the source of truth for dependency versions.

    3. `pnpm build` before `pnpm test` — all packages must build successfully before tests run.

    4. `steps.version.outputs.version` — uses `$GITHUB_OUTPUT` (modern syntax) instead of `$GITHUB_ENV` for scoped output between steps. `GITHUB_REF_NAME` strips the `refs/tags/` prefix automatically.

    5. `pnpm --filter @synapse-router/skill exec pnpm version $VERSION --no-git-tag-version` — bumps version in the package's local package.json to match the git tag. `--no-git-tag-version` prevents auto-commit.

    6. `publish --provenance --access public --no-git-checks` — provenance enables Sigstore-based build verification. `--access public` required for scoped packages (`@synapse-router/*`). `--no-git-checks` skips git status checks that fail in CI.

    7. `permissions: contents: write, id-token: write` — `contents: write` for Release creation. `id-token: write` for npm provenance OIDC token exchange (Pitfall 5).

    8. `gh release create --generate-notes` — auto-generates release notes from merged PRs. Uses `GITHUB_TOKEN` (built-in).

    9. Single `publish` job, no matrix needed. Both packages are co-versioned from the same git tag.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub runner -> npm registry | NPM_TOKEN secret is passed to the publish job. If the token is compromised, packages can be published maliciously |
| GitHub runner -> GitHub Releases | GH_TOKEN (GITHUB_TOKEN) has contents:write permission. Scoped to the current repository only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-07 | Spoofing | npm publish without provenance verification | mitigate | Both packages publish with `--provenance` flag, enabling Sigstore-based build attestation. Consumers can verify the published package was built from this exact CI workflow. `id-token: write` permission enabled for OIDC token exchange. |
| T-12-08 | Tampering | Malicious dependency injected via pnpm install | mitigate | `pnpm install --frozen-lockfile` prevents dependency drift. Lockfile is checked into the repository and reviewed. Any dependency change requires an explicit PR with lockfile update. |
| T-12-09 | Tampering | Tag push from unauthorized branch publishes untested code | accept | The workflow triggers on tag push regardless of branch. Tag creation is restricted to repository maintainers via GitHub branch protection rules. Testing (`pnpm test`) runs before publish as a safety net. |
| T-12-10 | Information Disclosure | NPM_TOKEN leaked in workflow logs | mitigate | GitHub Actions automatically masks secret values in logs (redacts `${{ secrets.NPM_TOKEN }}`). The token is scoped to Automation type (no 2FA, limited to CI use only). Token has publish-only permissions, not user account management. |
| T-12-11 | Elevation of Privilege | Workflow permissions broader than needed | mitigate | Permissions are explicitly scoped: `contents: write` (Release creation only) and `id-token: write` (provenance only). No `packages: write` or `actions: write`. Principle of least privilege applied. |
| T-12-12 | Denial of Service | Malformed tag causes infinite publish loop | accept | Tags are manually created by maintainers. The workflow publishes and exits — it does not create new tags. No risk of infinite loops. `--no-git-tag-version` in `pnpm version` prevents auto-tagging during publish. |
</threat_model>
